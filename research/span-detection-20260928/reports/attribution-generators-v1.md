# Generator attribution data v1

The [SynthPrompts development article](https://lyraaaa.dev/posts/developing-synthprompts.md)
and [v2 dataset card](https://huggingface.co/datasets/lyraaaa/synthprompts_v2_250k)
describe **user prompts generated by Gemma 4 31B**. They do not contain answers
from multiple target models. Gemma is the *prompt writer* there, so treating
that label as the author of a subsequent response would be wrong. I saved
2,000 English prompt candidates in a separate prompt-only pool for possible
future generation, with no answers and no API calls.

For later frozen-backbone attribution experiments, I assembled 11,864 existing
AI responses from two pinned, public primary releases:

| Source | Response rows | Distinct prompts | Published model labels | What the model label means |
| --- | ---: | ---: | ---: | --- |
| [Arena Prose](https://huggingface.co/datasets/woog/arena-prose-100-49-models) at `66298b561a69c6ed6a9a3c4c79eeedb1f754ba49` | 4,898 | 100 | 50 | Logical OpenRouter model ID; the release also records the reported request/response route, provider, canonical model and settings. |
| [LMArena human preference 140k](https://huggingface.co/datasets/lmarena-ai/arena-human-preference-140k) at `6322995ab34d7c2693e3f47dd13fa5caa0789a74`, first parquet shard only | 6,966 | ~3,454 before cross-source grouping | 53 | Published `model_a` or `model_b`; route, generation settings and exact backend revision are not in this release. |

The Arena Prose source contains 5,000 responses to the same 100 historically
collected, screened open-ended prose prompts. I retained its 4,898 published
mechanically eligible outputs: stop completion and at least 50 words. Its
source card explicitly says this mechanical gate does not establish substantive
prose or adjudicate all refusals. The 100 shared prompts give a useful paired
comparison across all 50 model labels, with 12–15 examples per class in each
holdout split after filtering. The repository slug still says 49 models, but
its pinned release has 50.

The LMArena sample comes from one of seven parquet shards. I kept one-turn,
English, text-only, non-code, non-math pairs with the same opening user prompt
on both sides, a prompt of 8–600 words, and both responses at least 80 words.
This is a heuristic prose filter, **not human review of every prompt**. It
retains both responses to each eligible pair. Models and topics in the first
shard may not represent the full preference dataset. Generation parameters
are null because the source does not provide them.

| Split | All responses | Arena Prose | LMArena preference | Prompt groups |
| --- | ---: | ---: | ---: | ---: |
| Train | 8,311 | 3,438 | 4,873 | 2,476 |
| Calibration | 1,767 | 715 | 1,052 | 531 |
| Test | 1,786 | 745 | 1,041 | 531 |

All models answering a prompt share one `group_id` and one split. Exact
normalized prompt matches and pairs with at least 85% overlap in five-word
shingles are grouped together. Across both sources, 3,554 distinct prompt
strings became 3,538 groups; 16 near-duplicate or normalized variants were
merged. Two duplicate response strings were removed. The manifest records
per-source model/category counts and data-file hashes. The response goes in
`text`; `prompt_text` stays separate. No text is rewritten or sanitized.

**Use separate tasks for the two sources.** There are zero shared *exact
published model-ID strings* between their 50 and 53 label sets. That does not
prove the underlying weights are all different: aliases and routing are not
mapped or verified. A unified 103-way exact-model benchmark would let a head
learn which corpus a response came from. The source-specific view manifests
define the prompt-group splits for a 50-way Arena Prose exploratory probe and
a LMArena-specific probe (37 classes meet the provisional minimum of 60 train,
10 calibration, and 10 test examples). A cross-source **family** check can use
the ten shared broad families; its family names come from an explicit prefix
taxonomy and are not proof of provider/backend identity. Source, prompt,
generation settings, publication date and response style remain possible
confounds. Those checks must be reported alongside attribution accuracy.

The source records retain published `generator_id`, separately reported
`canonical_model_reported`, `request_model`, `response_model`, `provider`,
generation parameters when available, prompt group/ID, source revision,
rights status, and prompt/response hashes. LMArena's `response_model` is null
because its published label does not establish the backend route. The
`self_identification_surface_flag` marks 103 responses containing a simple
AI/model self-reference pattern; future probes should measure accuracy both
with and without such cues. We have not inferred missing model names or exact
weight revisions.

The detector's current diverse parent already has `generator` labels, mainly
EditLens Claude/Gemini/GPT, paper SmolLM/Qwen, and MAGE machine-continuation
models. Those labels are useful for error breakdowns, but source/domain and
generator are often tightly coupled. The attribution corpus is kept separate.
An exact normalized response-text hash comparison against the detector's
diverse train, validation and test parents found **zero matches**; this does
not rule out semantic or near-duplicate overlap.

Rights differ. The [Arena Prose component notice](https://huggingface.co/datasets/woog/arena-prose-100-49-models/blob/main/LICENSE.md)
identifies upstream user prompts as CC BY 4.0 and does not claim a blanket
license for new outputs from third-party models. The
[LMArena card](https://huggingface.co/datasets/lmarena-ai/arena-human-preference-140k)
tags its dataset CC BY 4.0; individual model-output terms have not been
audited here. The SynthPrompts card tags its prompt dataset MIT. Keep these
derived text files local to research until reuse rights are reviewed.

attribution head was trained, and the active Repeat2 run was not changed.
